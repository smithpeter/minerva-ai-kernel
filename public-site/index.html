Minerva AI Kernel

CPU-local failure interpreter for CI/CD, agents, and ops. Minerva keeps a minimum local reasoning path available when models, tools, networks, code, configuration, or execution environments fail.

Open GitHub Read the local dry run

Narrow M0 claim

Observe a failure, structure it, and keep the next decision bounded.

M0 is intentionally small: it records command failure evidence, emits a structured local decision, applies policy, and preserves a run record for review.

Run and capture

Execute a command under observation and capture bounded stdout, stderr, exit code, cwd, duration, and runtime metadata.

Interpret locally

Use a CPU-local path for the minimum function, with no remote LLM required for the baseline flow.

Policy-check first

Model output is not authority. The structured decision is checked by policy before any consumer acts.

Save evidence

Write a local run record so humans and CI systems can inspect bounded, redacted failure context.

Safety boundary

LLM interprets. Policy authorizes. Executor acts.

Read-only by default

Default policy blocks shell execution, filesystem writes, destructive commands, credential access, unknown actions, and low-confidence actions.

Redacted evidence

Known sensitive values are redacted before model input and before persisted observations, decisions, run records, or CI artifacts are written.

Diagnostic CI output

CI summaries and artifacts are bounded evidence. The observed command exit code remains the gate.

Non-claims

What M0 does not claim

  • M0 does not auto-repair systems.
  • M0 is not a full AIOps platform.
  • M0 does not replace CI, monitoring, tests, incident platforms, or human review.
  • M0 does not execute arbitrary model-generated shell commands.
  • M0 does not require a remote LLM for the minimum local path.
  • The smoke eval is a wiring and policy signal, not a production reliability benchmark.
