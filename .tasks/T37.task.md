# Task: Add local install environment readiness check

- Status: done
- GitHub Issue: https://github.com/smithpeter/minerva-ai-kernel/issues/37
- Owner Lane: Release / Integration
- Allowed Files: `scripts/check-release-readiness.py`, `tests/`, `docs/`, `README.md`, `CHANGELOG.md`, `.tasks/`

## Goal

Turn the T36 release dry-run caveat into a repeatable local readiness signal:
users should be able to detect whether their current Python/venv environment has
the build backend needed for the documented offline editable install path before
they hit a confusing install failure.

## Acceptance Criteria

- Extend the release readiness checker, or add a focused helper connected to it,
  so local users can verify offline editable install prerequisites without
  network access.
- Report whether `setuptools.build_meta` is importable in the target interpreter
  or fresh venv, and explain the next action without downloading dependencies.
- Add regression coverage for pass, fail, and skipped behavior.
- Update relevant docs and changelog with the new command and interpretation.
- Preserve project safety boundaries: no dependency downloads, no package
  publish, no external account operations, and no VoxSign state.

## Non-Goals

- Do not publish a release.
- Do not download dependencies.
- Do not solve arbitrary Python packaging environments.
- Do not touch VoxSign files or workflows.

## Output

Implemented `local_install_backend` in `scripts/check-release-readiness.py`.
The checker now probes `setuptools.build_meta` in the current target
interpreter by default, can create and probe a temporary fresh venv with
`--install-backend fresh-venv`, and can explicitly skip the local install
backend probe with `--install-backend skip`. The check reports pass/fail/skipped
status plus a bounded next action and does not invoke pip or download
dependencies.

Updated regression coverage in `tests/test_release_readiness_check.py` for
backend pass, fail, and skipped behavior. Updated README, release readiness,
local dry-run, CI/domain verification docs, and changelog with the new commands
and interpretation.
