# Task: Add CI log analysis command surface

- Status: done
- GitHub Issue: https://github.com/smithpeter/minerva-ai-kernel/issues/54
- Owner Lane: Integration / CI
- Allowed Files: `minerva_kernel/`, `tests/`, `docs/`, `examples/`, `.tasks/`

## Goal

Add the first CLI surface for AIOps/CI ecosystem use beyond wrapping a command:
analyze existing CI logs or JUnit-like artifacts into Minerva observations and
decisions.

## Plan-Eng Review

### Scope Challenge
- Accepted scope: design and implement a small local `ci analyze` or equivalent
  command for bounded log input.
- Reduced or deferred scope: do not integrate with hosted CI APIs or require
  credentials.

### What Already Exists
- Existing code/docs reused: `observe`, CI renderers, observation schema,
  redaction, and integration recipes.
- Existing tests/evals reused: CLI tests, CI renderer tests, and redaction tests.

### NOT In Scope
- Direct GitHub/GitLab API calls.
- Auto-repair.
- Full JUnit parser if a bounded first JSON/text path is safer.

### Architecture / Flow

```text
log file / artifact
  -> bounded read + redaction
  -> observation.v0
  -> diagnosis + policy
  -> optional CI summary/artifact
```

### State / Decision Diagram

```text
[input path] -> [read bounded content] -> [observation] -> [decision]
      |                 |                   |
      v                 v                   v
 [missing]        [oversized]          [policy blocked]
      |                 |                   |
      v                 v                   v
 [error]          [truncate]           [clear status]
```

### Failure Modes

| Failure mode | Covered by test/eval | Error handling | User-visible outcome |
| --- | --- | --- | --- |
| CI log contains secrets | yes | redaction before model input/output | clear redaction summary |
| Log file is too large | yes | bounded tail/truncation | clear bounded output |
| Artifact path missing | yes | CLI exits with error | clear failure |

## Acceptance Criteria

- Add a local CI log analysis command or documented equivalent CLI subcommand.
- Add tests for missing input, redaction, and successful diagnosis.
- Add example usage for GitHub Actions or generic CI.
- Preserve no auto-repair and policy-gated behavior.
- No critical Plan-Eng failure-mode gap remains open.

## Non-Goals

- Do not call remote CI APIs.
- Do not require network access.
- Do not execute model-selected actions automatically.

## Output

Completed CI log analysis command surface.

- Added `minerva_kernel.ci_analyze` to turn existing CI log files into bounded
  `observation.v0` records with `source: ci_log`.
- Added `minerva ci-analyze LOG --job-name NAME --tail-chars N`.
- Added tests for successful diagnosis, redaction before provider prompt,
  missing log errors, and bounded large-log tails.
- Added `examples/ci-log-analysis.md` and linked it from examples README.
- The command is local-only, credential-free, and does not execute selected
  actions automatically.
