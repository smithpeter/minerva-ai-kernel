## Goal

Create a stable release operations dashboard that summarizes release readiness,
Plan-Eng workflow health, eval status, task queue state, and local install
readiness in one bounded local command.

## Plan-Eng Review

### Scope Challenge
- Accepted scope: add a local summary command/script and tests using existing
  readiness checks.
- Reduced or deferred scope: no GitHub API dependency and no public deploy.

### What Already Exists
- Existing code/docs reused: release readiness checker, AI-team status,
  Plan-Eng check, eval commands, preflight.
- Existing tests/evals reused: release readiness tests, Plan-Eng workflow tests,
  AI-team preflight tests.

### NOT In Scope
- Publishing a release.
- Opening PRs or pushing commits.
- External domain/DNS live checks beyond existing optional readiness paths.

### Architecture / Flow

```text
local checks
  -> bounded status collector
  -> release_ops_status.v0
  -> human-readable summary
```

### State / Decision Diagram

```text
[check runs] -> [all pass] -> [ready summary]
      |             |
      v             v
 [check fails]  [dirty worktree]
      |             |
      v             v
 [not ready]   [not ready]
```

### Failure Modes

| Failure mode | Covered by test/eval | Error handling | User-visible outcome |
| --- | --- | --- | --- |
| A subcheck fails | yes | dashboard reports failed check | clear status |
| Output leaks local secrets | yes | bounded known fields only | clear safe output |
| Script requires network unexpectedly | yes | tests use local-only mode | clear failure |

## Output

Added `scripts/release-ops-dashboard.py`, a local-only release operations
dashboard that emits `release_ops_status.v0` and summarizes Plan-Eng-Review,
AI-team status, eval smoke, CPU eval fixture, local release readiness, task
queue completion, and worktree cleanliness. The release readiness subcheck uses
`--skip-external --install-backend current`, so it does not call external
services by default. Added tests for ready output, failed subchecks, pending
tasks, dirty worktrees, and CPU eval decision handling. Documented usage in
README and release readiness docs.
