# Task: Add domain brand contamination guard to release readiness

- Status: pending
- GitHub Issue: https://github.com/smithpeter/minerva-ai-kernel/issues/40
- Owner Lane: Release / Integration
- Allowed Files: `scripts/check-release-readiness.py`, `tests/`, `docs/`, `README.md`, `CHANGELOG.md`, `.tasks/`

## Goal

Prevent `minervakernel.com` from being marked ready when it serves another
project's certificate or page content.

## Evidence

On 2026-05-08, readiness for commit
`109b524467b6fb6cf78f00c86416b070c4691226` showed CI green and DNS resolving,
but TLS failed. Direct TLS diagnostics showed the server certificate subject was
`CN=test.voxsign.net` and did not match `minervakernel.com`. Fetching with
certificate verification disabled returned a VoxSign page title and VoxSign
content. This is a release blocker and a project isolation risk.

## Acceptance Criteria

- Extend release readiness or add a documented guard so public domain checks
  require Minerva brand/content signals and reject VoxSign markers.
- Record the current domain blocker and required external fix:
  `minervakernel.com` must serve a certificate valid for `minervakernel.com` and
  a Minerva page, not VoxSign.
- Add tests for brand pass/fail behavior without network access.
- Update docs/changelog with the domain contamination blocker and verification
  command.

## Non-Goals

- Do not deploy to the server.
- Do not modify VoxSign files or workflows.
- Do not bypass TLS for a passing readiness result.
