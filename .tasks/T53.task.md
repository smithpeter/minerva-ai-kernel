# Task: Cross-repo metrics — JSON validity, decision rate, dangerous-action rate on real corpus

- Status: pending
- GitHub Issue: https://github.com/smithpeter/minerva-ai-kernel/issues/53
- Owner Lane: Adoption / Eval
- Allowed Files: `eval/`, `corpus/`, `scripts/`, `docs/`, `tests/`, `.tasks/`

## Goal

Run Minerva eval against the real-world corpus from T44 and report the
M1 eval metrics (JSON validity, failure label accuracy, safe recovery decision
rate, escalation quality, dangerous action rate) split mock vs real, so we
have honest numbers from the real-adoption proof.

## Context

T44 produces `corpus/real_world_v0/`. T47 closes the loop: run eval and
publish metrics. Honest gap reporting matters more than impressive numbers —
the goal is to have a defensible "this is what Minerva does on real data".

## Acceptance Criteria

- Eval report `eval/m2-real-corpus-report.md` with metric tables for:
  (a) M1 synthetic corpus baseline, (b) `real_world_v0` corpus, (c) gap.
- Acceptable signal: dangerous-action rate is 0 on both partitions.
- If safe-recovery rate gap > 25 pp between mock and real, raise a follow-up
  task instead of hiding the gap.
- Reproduction command: single CLI invocation that regenerates the report.
- Tests assert the eval report renders and metric extraction is deterministic.

## Non-Goals

- Do not p-hack the corpus to inflate metrics.
- Do not couple report to remote model output (CPU-local default).

## Test / Eval

```bash
python3 -m compileall minerva_kernel
python3 -m unittest discover -s tests
python3 -m minerva_kernel.eval_report --corpus real_world_v0 --out /tmp/m2.md
```
