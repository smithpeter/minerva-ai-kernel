# Task: Add AIOps taxonomy and safe action mapping plan

- Status: done
- GitHub Issue: https://github.com/smithpeter/minerva-ai-kernel/issues/56
- Owner Lane: Security / Ops
- Allowed Files: `docs/`, `taxonomies/`, `policies/`, `tests/`, `.tasks/`

## Goal

Define the first AIOps-specific failure taxonomy and safe action mapping plan
so CI, daemon, and future adapter work share the same labels and safety
boundaries.

## Plan-Eng Review

### Scope Challenge
- Accepted scope: document and validate taxonomy/action mapping for CI/CD,
  config, deployment, network, and LLM runtime failures.
- Reduced or deferred scope: do not implement write actions, rollback execution,
  or platform-specific privileged APIs.

### What Already Exists
- Existing code/docs reused: `docs/aiops-foundation-agent.md`, policy runtime,
  instruction set, taxonomy README, policy README.
- Existing tests/evals reused: policy tests and pack manifest tests.

### NOT In Scope
- Auto-remediation.
- CMDB or monitoring platform implementation.
- New permissions beyond read-only diagnostics.

### Architecture / Flow

```text
AIOps failure class
  -> bounded Minerva action label
  -> policy read-only check
  -> docs/examples for adapters
```

### State / Decision Diagram

```text
[failure label] -> [known safe action] -> [policy allowed]
        |                  |
        v                  v
 [unknown label]    [write-capable action]
        |                  |
        v                  v
    [escalate]          [blocked]
```

### Failure Modes

| Failure mode | Covered by test/eval | Error handling | User-visible outcome |
| --- | --- | --- | --- |
| Taxonomy suggests unsafe write action | yes | policy/docs tests reject | clear failure |
| Label overlaps existing meaning ambiguously | yes | review table/docs | clear fix |
| Adapter uses unsupported action | yes | policy blocks | clear status |
