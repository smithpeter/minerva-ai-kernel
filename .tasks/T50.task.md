# Task: Add real local provider path to CPU model eval

- Status: done
- GitHub Issue: https://github.com/smithpeter/minerva-ai-kernel/issues/50
- Owner Lane: Eval / Research
- Allowed Files: `minerva_kernel/`, `tests/`, `evals/`, `docs/`, `.tasks/`

## Goal

Advance the complete Minerva vision by making the CPU model eval harness runnable
against a real local OpenAI-compatible provider while preserving the offline
fixture path used by tests and CI.

## Plan-Eng Review

### Scope Challenge
- Accepted scope: add a `local-openai` CPU eval provider mode, candidate
  metadata defaults, latency measurement for real provider runs, tests with a
  mocked endpoint, and documentation.
- Reduced or deferred scope: do not download models, start Ollama, expand the
  corpus, or claim real benchmark results in this task.

### What Already Exists
- Existing code/docs reused: `LocalOpenAICompatibleProvider`,
  `ModelProviderResponseAdapter`, `cpu_model_eval` report builder, provider
  health checks, and CPU eval docs.
- Existing tests/evals reused: CPU eval unit tests, provider test fixtures,
  eval smoke, and full unittest discovery.

### NOT In Scope
- Real qwen/smol/granite model execution on this machine.
- Persistent benchmark artifacts from a non-fixture model.
- Remote model fallback.

### Architecture / Flow

```text
eval cases
  -> build_prompt_messages
  -> fixture provider OR LocalOpenAICompatibleProvider
  -> decision.v0 JSON
  -> policy + eval scoring
  -> cpu_model_eval_report.v0
```

### State / Decision Diagram

```text
[fixture mode] -> [checked-in response] -> [deterministic report]

[local-openai mode] -> [local endpoint reachable] -> [decision.v0] -> [scored report]
          |                    |
          v                    v
 [endpoint unavailable]   [invalid response]
          |                    |
          v                    v
 [structured fallback: ask_bigger_llm, remote_fallback_attempts=0]
```

### Failure Modes

| Failure mode | Covered by test/eval | Error handling | User-visible outcome |
| --- | --- | --- | --- |
| Local endpoint unavailable | yes | provider returns structured fallback | clear report row |
| Local endpoint returns invalid JSON | yes | provider returns structured fallback | clear report row |
| CLI local-provider wiring drifts | yes | unit test patches endpoint and asserts report | clear test failure |
