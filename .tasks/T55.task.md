# Task: Extend minervad with local diagnosis API

- Status: done
- GitHub Issue: https://github.com/smithpeter/minerva-ai-kernel/issues/55
- Owner Lane: Kernel / Daemon
- Allowed Files: `minerva_kernel/`, `tests/`, `docs/`, `.tasks/`

## Goal

Move minervad from a health-only skeleton toward an embeddable AIOps agent by
adding a local-only diagnosis endpoint for bounded `observation.v0` input.

## Plan-Eng Review

### Scope Challenge
- Accepted scope: add a minimal localhost diagnosis API and tests.
- Reduced or deferred scope: no auth, remote control plane, persistent daemon
  state, or write-capable actions in this task.

### What Already Exists
- Existing code/docs reused: `minerva_kernel.daemon`, SDK diagnosis helpers,
  provider abstraction, policy runtime, and minervad docs.
- Existing tests/evals reused: daemon tests, SDK tests, policy tests.

### NOT In Scope
- Public network exposure.
- Service installation changes.
- Automatic execute-action calls.

### Architecture / Flow

```text
HTTP POST /diagnose
  -> parse observation.v0
  -> diagnose_observation
  -> policy result
  -> JSON response
```

### State / Decision Diagram

```text
[request] -> [valid JSON] -> [observation.v0] -> [diagnosis response]
     |            |                 |
     v            v                 v
 [bad method] [bad JSON]     [schema invalid]
     |            |                 |
     v            v                 v
   [405]        [400]             [400]
```

### Failure Modes

| Failure mode | Covered by test/eval | Error handling | User-visible outcome |
| --- | --- | --- | --- |
| Invalid JSON body | yes | HTTP 400 | clear error |
| Non-observation payload | yes | HTTP 400 | clear error |
| Diagnosis policy blocked | yes | response includes policy decision | clear status |
