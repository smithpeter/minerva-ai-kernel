# Task: Add --corpus argument to eval_smoke CLI (T50 unblock)

- Status: done
- GitHub Issue: https://github.com/smithpeter/minerva-ai-kernel/issues/55
- Owner Lane: Adoption / Eval (hotfix)
- Allowed Files: `minerva_kernel/eval_smoke.py`, `tests/`, `evals/`, `corpus/`, `docs/`, `.tasks/`

## Goal

Extend `minerva_kernel.eval_smoke` CLI to accept a `--corpus <slice_name>`
argument so the M1/M2 eval can target named corpus partitions (mock vs
`real_world_v0` from T44) without hardcoding paths.

## Context

T44 ships `corpus/real_world_v0/entries.jsonl` with 50 redacted real-world
GitHub Actions failure-log entries. T44's acceptance command is:

```bash
python -m minerva_kernel.eval_smoke --corpus real_world_v0
```

That command currently fails with `unrecognized arguments: --corpus` because
eval_smoke's CLI only accepts an optional `cases_path` positional. T44 is
stuck in_progress because fixing eval_smoke is outside its Allowed Files.
T49 is the focused hotfix.

## Acceptance Criteria

- `python -m minerva_kernel.eval_smoke --corpus real_world_v0` succeeds and
  reports metrics for the real-world slice.
- `python -m minerva_kernel.eval_smoke --corpus mock` (or default with no
  flag) preserves prior synthetic-eval behavior with no regression.
- `--corpus <name>` resolves to `corpus/<name>/entries.jsonl` (or the
  matching path under `evals/` if that's where slices live).
- New unit test asserts `--corpus real_world_v0` end-to-end (using a small
  fixture if 50-entry load is too slow for CI).
- Existing tests still pass: `python3 -m unittest discover -s tests`.
- Help text (`--help`) documents the new flag clearly.

## Non-Goals

- Do not change eval logic, redaction, or decision schema — pure CLI surface
  + path resolution.
- Do not modify T44's corpus contents.

## Test / Eval

```bash
python3 -m unittest discover -s tests
python3 -m minerva_kernel.eval_smoke --corpus real_world_v0
python3 -m minerva_kernel.eval_smoke --help
```
