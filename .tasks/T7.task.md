# Task: Implement `minerva observe -- <command>`

- Status: done
- GitHub Issue: https://github.com/smithpeter/minerva-ai-kernel/issues/4
- Owner Lane: Kernel
- Allowed Files: `minerva_kernel/`, `tests/`, `docs/`, `examples/`

## Goal

Make Minerva's primary M0 workflow usable: run a command, capture a bounded observation, diagnose it, policy-check it, and save a run record.

## Acceptance Criteria

- `minerva observe -- <command>` runs the command with a timeout and captures exit code, stdout tail, stderr tail, duration, cwd, and runtime metadata.
- The command creates an Observation Schema v0 record with redaction applied before model input and saved output.
- It obtains a decision through the provider abstraction and validates it through Policy Runtime v0.
- It saves a run record under `.minerva/runs/`.
- Tests cover successful command, failing command, timeout or command-not-found behavior, redaction, and saved run record shape.

## Non-Goals

- Do not implement auto-repair.
- Do not execute model-selected actions.
- Do not collect full environment variables by default.

## Test / Eval

```bash
python3 -m compileall minerva_kernel
python3 -m unittest discover -s tests
```

## Output

Implemented `minerva observe -- <command>` in the CLI.

- Redacts observations before provider input and uses redacted observation/decision payloads in saved run records.
- Routes observations through the provider abstraction, validates decisions with Policy Runtime v0, and saves run records under `.minerva/runs/`.
- Added tests for successful commands, failing commands, timeout behavior, command-not-found behavior, redaction, and run record shape.
