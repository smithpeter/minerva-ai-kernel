# Task: Add ecosystem adapter event reporting guide

- Status: done
- GitHub Issue: https://github.com/smithpeter/minerva-ai-kernel/issues/58
- Owner Lane: Docs / Ecosystem
- Allowed Files: `docs/`, `examples/`, `adapters/`, `tests/`, `README.md`, `.tasks/`

## Goal

Make it clear how external CI, AIOps, and agent platforms can embed Minerva by
sending observations and receiving structured decisions without adopting a full
platform or granting unsafe permissions.

## Plan-Eng Review

### Scope Challenge
- Accepted scope: add adapter/event reporting guide and examples for embedding
  Minerva in CI/AIOps/agent systems.
- Reduced or deferred scope: no production SDK for specific third-party
  platforms and no network control plane.

### What Already Exists
- Existing code/docs reused: integration recipes, SDK examples, pack manifests,
  AIOps foundation docs, CI renderers.
- Existing tests/evals reused: SDK example tests and pack manifest tests.

### NOT In Scope
- Vendor-specific adapters requiring credentials.
- Hosted service API.
- Auto-execution of actions.

### Architecture / Flow

```text
external platform
  -> observation.v0
  -> Minerva diagnose / minervad API
  -> decision.v0 + policy
  -> platform annotation / escalation
```

### State / Decision Diagram

```text
[platform event] -> [observation.v0] -> [decision.v0] -> [policy result]
        |                  |                 |
        v                  v                 v
 [missing fields]    [redacted input]   [blocked/allowed]
        |                                    |
        v                                    v
   [reject event]                       [report only]
```

### Failure Modes

| Failure mode | Covered by test/eval | Error handling | User-visible outcome |
| --- | --- | --- | --- |
| Adapter omits required observation field | yes | schema validation docs/tests | clear failure |
| Adapter leaks secret in logs | yes | redaction examples | clear redaction |
| Platform treats decision as authorization | yes | docs emphasize policy gate | clear boundary |

## Acceptance Criteria

- Add guide for external platforms to emit observations and consume decisions.
- Include at least one CI-style and one AIOps-style event example.
- Clarify that policy authorization remains separate from model decisioning.

- No critical Plan-Eng failure-mode gap remains open.
