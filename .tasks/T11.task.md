## Goal

Make it easy for users to contribute failure cases without leaking secrets or needing to understand the whole codebase.

## Acceptance Criteria

- Add a clear contribution guide for failure cases.
- Explain required fields, redaction expectations, examples, and review checklist.
- Include a simple issue template or documentation section for submitting a failure case.
- Explain what not to submit: secrets, private logs, full env dumps, proprietary source.
- Link the guide from README or CONTRIBUTING.

## Non-Goals

- Do not add a web form.
- Do not ask users to upload raw unredacted logs.
- Do not change runtime code.
