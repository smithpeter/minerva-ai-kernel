# Task: Pilot adoption on a sandbox repo (minerva-pilot-sandbox)

- Status: pending
- GitHub Issue: https://github.com/smithpeter/minerva-ai-kernel/issues/52
- Owner Lane: Adoption / Integration
- Allowed Files: `examples/`, `docs/`, `pilot/`, `.tasks/`
  (note: actual pilot repo lives outside this repo at `smithpeter/minerva-pilot-sandbox`; this card tracks the local artifacts that prove the pilot)

## Goal

Stand up a public sandbox repo (`smithpeter/minerva-pilot-sandbox`) that
mirrors a small Python library skeleton, installs the T43 Action, and runs
Minerva on every push for 7 consecutive days. Local artifacts here document
the result.

## Context

This is the first end-to-end "external" adoption. Even though the sandbox is
owned by the same org, treat it as if a stranger were adopting Minerva — the
config, instructions, and dependencies must be self-contained.

## Acceptance Criteria

- `pilot/sandbox-runbook.md` documents how the sandbox repo was set up
  (commands + workflow yml).
- `pilot/sandbox-7day-evidence.md` lists 7+ Actions runs (URLs) where Minerva
  produced a summary + artifact, with date stamps.
- At least one run includes a real failure (e.g. broken test) where Minerva's
  decision is captured.
- No auto-repair; observation + decision only.
- Sandbox repo's workflow yml is also checked in here at
  `examples/sandbox-workflow.yml` so future adopters can copy it.

## Non-Goals

- Do not push observations from the sandbox back into this repo's corpus
  automatically.
- Do not enable any model-selected execution.
