# Task: Add eval data loop artifact schema

- Status: done
- GitHub Issue: https://github.com/smithpeter/minerva-ai-kernel/issues/52
- Owner Lane: Eval / Data
- Allowed Files: `minerva_kernel/`, `tests/`, `docs/`, `evals/`, `.tasks/`

## Goal

Create the first data-loop path from saved Minerva run records into bounded,
reviewable eval corpus candidate artifacts.

## Plan-Eng Review

### Scope Challenge
- Accepted scope: define a local artifact schema and command/helper that turns
  `.minerva/runs/*.json` records into redacted candidate cases for human review.
- Reduced or deferred scope: do not automatically merge candidates into the
  official corpus and do not train models.

### What Already Exists
- Existing code/docs reused: run record schema from `observe`, redaction,
  failure corpus loaders, and eval docs.
- Existing tests/evals reused: run artifact tests, redaction tests, and eval
  report tests.

### NOT In Scope
- Automatic labeling by remote LLMs.
- Uploading telemetry.
- Mutating official eval files without human review.

### Architecture / Flow

```text
.minerva/runs/run.json
  -> validate run record
  -> extract observation + decision + policy
  -> redact/bound fields
  -> eval_candidate.v0 JSONL
```

### State / Decision Diagram

```text
[run record] -> [valid] -> [candidate emitted] -> [human review]
      |             |              |
      v             v              v
 [missing]   [invalid schema]  [not auto-merged]
      |             |
      v             v
   [skip]       [report error]
```

### Failure Modes

| Failure mode | Covered by test/eval | Error handling | User-visible outcome |
| --- | --- | --- | --- |
| Run record includes secrets | yes | redaction and bounded output | clear candidate artifact |
| Bad run record schema | yes | command reports error | clear failure |
| Candidate is mistaken for approved corpus | yes | separate schema/name and docs | clear distinction |

### Test / Eval Plan
- Required command: `python3 -m unittest discover -s tests`
- Additional focused check: add unit tests for candidate artifact generation.

### Parallelization
- Can run parallel with T51 if write conflicts are avoided in eval docs/tests.
- Parallel lanes, if any: coordinate test file names before editing.

### Review Readiness
- Diff review focus: no secret leakage, no auto-merge, bounded artifact fields.
- Release or docs impact: document the data loop as review-first.

## Acceptance Criteria

- Define `minerva_eval_candidate.v0` artifact shape.
- Add local helper or CLI path to render candidate JSONL from run records.
- Add tests for happy path, redaction, and malformed input.
- Document that candidates require human review before corpus inclusion.
- No critical Plan-Eng failure-mode gap remains open.

## Non-Goals

- Do not upload data.
- Do not call remote models.
- Do not automatically modify official eval corpora.
