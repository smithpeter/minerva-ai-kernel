# Task: Add eval candidate review ledger

- Status: done
- GitHub Issue: https://github.com/smithpeter/minerva-ai-kernel/issues/60
- Owner Lane: Eval / Data
- Allowed Files: `minerva_kernel/`, `evals/`, `tests/`, `docs/`, `.tasks/`

## Goal

Add a review ledger for eval candidates so generated candidate cases can be
accepted, rejected, or deferred with human review notes before entering the
stable corpus.

## Plan-Eng Review

### Scope Challenge
- Accepted scope: ledger schema, examples, and validation.
- Reduced or deferred scope: no automatic corpus mutation and no remote review
  service.

### What Already Exists
- Existing code/docs reused: `minerva_kernel.eval_candidates`,
  `evals/README.md`.
- Existing tests/evals reused: eval candidate tests.

### NOT In Scope
- Auto-approving model-generated cases.
- Rewriting the stable corpus.

### Architecture / Flow

```text
candidate jsonl
  -> human review ledger
  -> accepted/rejected/deferred status
  -> later corpus update
```

### State / Decision Diagram

```text
[needs_human_review] -> [accepted]
          |              [rejected]
          v              [deferred]
    [missing note] -> [invalid ledger]
```

### Failure Modes

| Failure mode | Covered by test/eval | Error handling | User-visible outcome |
| --- | --- | --- | --- |
| Ledger approves without reviewer | yes | validation fails | clear error |
| Duplicate candidate id | yes | validation fails | clear error |
| Accepted case lacks expected labels | yes | validation fails | clear error |

### Test / Eval Plan

- Additional focused check: validate example ledger JSONL.

### Parallelization
- Can run independently of daemon and release tasks.
- Parallel lanes, if any: docs and validator tests.

### Review Readiness
- Diff review focus: no automatic corpus promotion.
- Release or docs impact: closes eval data-loop review gap.
