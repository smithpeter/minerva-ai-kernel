# Task: Publish reusable minerva-action GitHub Action

- Status: done
- GitHub Issue: https://github.com/smithpeter/minerva-ai-kernel/issues/49
- Owner Lane: Adoption / Integration
- Allowed Files: `action/`, `.github/workflows/`, `examples/`, `docs/`, `README.md`, `CHANGELOG.md`, `tests/`, `.tasks/`

## Goal

Package Minerva as a reusable GitHub Action so any third-party repo can drop
a single `uses: smithpeter/minerva-action@v0` step into their CI and start
producing structured failure observations and decisions on every workflow run.

## Context

M0 + M1 made `minerva observe` work locally and inside this repo's own CI.
M2 Adoption lane proves Minerva is useful outside this repo. Step 1 is shipping
a callable Action that wraps `minerva observe -- <command>` with a clean input
schema, redaction defaults, and a deterministic markdown summary upload.

## Acceptance Criteria

- `action.yml` defined at repo root or `action/action.yml` with inputs:
  `command` (required), `summary-path`, `artifact-name`, `redaction-mode`
- Composite action that installs Minerva from PyPI or this repo and runs
  `minerva observe --` against the given command, then writes the v0 summary
  + artifact.
- `examples/minerva-action-demo.yml` workflow file using the action against a
  trivial command (e.g. `pytest -q`).
- README section "Use as a GitHub Action" with copy-pasteable yml block.
- Unit/integration test asserts action.yml is valid and required inputs exist.
- Action does NOT auto-execute model-selected actions (M0 safety boundary
  preserved): observation + decision only, no remediation.

## Non-Goals

- Do not publish to GitHub Marketplace yet (a later T48 step covers adopters).
- Do not modify VoxSign or any unrelated repository state.
- Do not require remote model access; CPU-local default per M0 contract.

## Test / Eval
